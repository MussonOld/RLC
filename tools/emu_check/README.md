# Сверка переноса на C с образом прошивки

Каждая функция из `src/nrlc_funcs.c` запускается в эмуляторе Cortex-M4 (Unicorn) рядом с
оригиналом из `nRLC_2_0_12_FREEWARE.hex` на одинаковом случайном начальном состоянии.
Сравниваются возвращаемое значение, итоговая RAM (без области стека) и порядок записей в
регистры периферии и во флеш. Внешние вызовы переноса (`FUN_xxxxxxxx`) связываются с
оригинальным кодом из образа, заглушки HAL-эквивалентов в тесте перенаправляются на оригинал.

Запуск (нужны `arm-none-eabi-gcc`, `unicorn==2.1.3`, `capstone`, заголовки CMSIS в `/tmp/cm`):

    cd tools/emu_check
    python3 run_checks.py 40      # 40 случайных наборов на функцию, итоги в RESULTS.md

Важно: версия Unicorn 2.1.4 неверно исполняет Thumb-код, где IT-блок идёт перед условным
переходом (теряются инструкции и обновление флагов); 2.1.3 и 2.0.1 исполняют верно.

Файлы: `harness.py` - запуск и сравнение, `run_checks.py` - наборы входных данных,
`dbg.py` - вспомогательные функции для разбора расхождений, `link.ld` - скрипт линковки переноса.
